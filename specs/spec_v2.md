## 0. Context from Person 2's Week 1 findings

Schema check (817 / 4507 / 4321 rows, 0 missing values across all three) revealed datasets differ in how a labeled answer is obtained:

| Dataset | Has labeled text already? | Processing mode |
|---|---|---|
| TruthfulQA | Yes — `correct_answers[]` (label=TRUE), `incorrect_answers[]` (label=FALSE) | **Teacher-forced** — feed text through model, no generation |
| HaluEval (general) | Yes — `chatgpt_response` + `hallucination` (yes/no) | **Teacher-forced** — response was generated by ChatGPT, not our models; we only run it through Qwen/Llama for activations |
| SimpleQA | No — only `problem` + reference `answer` | **Generated** — our model generates the answer, then auto-labeled per Spec v1 §3 |

This distinction is now a required field in the schema below (`source`). Extraction pipeline must branch on it per dataset.

## 1. Activation-Extraction Schema

Per token, per layer, cache a record with these fields:

```
{
  example_id:      str   # unique row id, joins back to labeled_dataset_v1
  dataset_name:    str   # truthfulqa | halueval | simpleqa
  model_name:      str   # qwen2.5-1.5b | llama-3.2-3b
  split:           str   # train | val | test  (from Spec v1 §2)
  source:          str   # "teacher_forced" | "generated"
  layer_index:     int   # 0–28 (29 layers, both models)
  token_position:  int   # 0-indexed, position within the answer span only
                          # (not the prompt/question — hook starts at first answer token)
  hidden_state:    float32[hidden_dim]   # 1536 (Qwen) or 3072 (Llama)
  label:           int   # 1 = true, 0 = hallucination
}
```

Notes:
- `token_position` is always relative to the **answer span**, never the full prompt — this keeps TruthfulQA/HaluEval (teacher-forced) and SimpleQA (generated) comparable on the same ERDP axis.
- TruthfulQA: each `correct_answers[i]` / `incorrect_answers[i]` entry is cached as its own example (same `example_id` root, suffixed), not just `best_answer` — gives more training signal per question.
- For class balance on TruthfulQA, cap `incorrect_answers` sampled per question to the count of `correct_answers` available for that question (avoid swamping with negatives).

## 2. GO/NO-GO Benchmark Protocol (Week 3)

- **Dataset + model:** HaluEval (general) + Qwen2.5-1.5B.
  Reason: largest set (4507), binary label already exists with zero auto-labelling risk (unlike SimpleQA) and zero answer-selection ambiguity (unlike TruthfulQA's multi-answer lists) — cleanest possible first signal check.
- **Pass bar:** mass-mean probe AUROC must exceed the semantic-entropy baseline AUROC by **≥ 0.05**, at matched inference compute (Person 2's baseline code from Week 1 skeleton).
- **GO** → continue as planned, paper claims "earlier + cheaper than existing methods."
- **NO-GO** → pivot to pre-registered fallback (below), paper claims a characterisation finding instead.

## 3. Pre-registered NO-GO Fallback

If the probe does not clear the bar: narrow scope to answering — **does the early-layer truth-direction signal correlate with the *type* of hallucination** (e.g. factual slip vs. fabricated entity vs. off-topic), not merely its presence? HaluEval's `hallucination_spans` field (already present in the data) supports this without extra labelling work.

## 4. Activation-Cache Storage Estimate

Formula: `layers × avg_token_count × hidden_dim × num_examples × num_models × 4 bytes`

Placeholder using avg_token_count = 50 (**unverified — Person 3 must compute actual mean answer length per dataset before Week 3 full-scale run and plug in real numbers**):

- Qwen2.5-1.5B (hidden=1536): 29 × 50 × 1536 × 9,645 ≈ 20.4 GB
- Llama-3.2-3B (hidden=3072): 29 × 50 × 3072 × 9,645 ≈ 40.8 GB
- **Combined: ≈ 61 GB**

**Subsampling rule:** if combined cache exceeds the chosen platform's storage quota (check Kaggle/Colab limits before Week 3), cache only every 4th layer (0, 4, 8, ... 28 → 8 layers instead of 29) as the default reduction — preserves enough resolution for the per-layer ablation (Week 7) while cutting storage ~3.6x. If still over budget, subsample SimpleQA/TruthfulQA negative examples next (HaluEval stays fully cached — it's the GO/NO-GO dataset).
